# Final release runbook

1. Review [MaxRepo security audit](https://github.com/ermaclorenzo57-lgtm/GitHubManageApk/actions/workflows/security-audit.yml) and [CodeQL](https://github.com/ermaclorenzo57-lgtm/GitHubManageApk/actions/workflows/codeql.yml). Both must finish; review every finding. The dependency job covers resolved Maven runtime/compile and available buildscript dependencies, not every plugin or SDK.
2. Enable Dependabot alerts, dependency graph, secret scanning, push protection and private vulnerability reporting under Settings > Security. Dependabot cannot see Gradle manifests inside ZIPs, so direct OSV scans supplement it.
3. Under Settings > Branches or Rulesets protect main, block deletion/force pushes, require PRs and successful checks, including security checks once available. For a solo maintainer avoid an approval requirement that cannot be satisfied. Review changes to workflows before merging. Keep environment restricted to main.
4. Install production build 10002, then install the final production build (10004 or newer) without uninstalling. Verify account, settings, files and launch. If already on 10002 after upgrading, record what happened. Do not downgrade or delete app data merely to test.
5. Test logout, account switch, denied permissions, interrupted network, and APK mismatch warnings using a disposable test repository and minimum-scope token.
6. Review privacy notice, third-party licenses, dependency integrity and distribution terms; record evidence. Enable private vulnerability reporting.
7. Once all release gates are satisfied, download the signed build from the exact successful production run, extract MaxRepo-v1.0.0.apk and SHA256SUMS, and create a release tagged v1.0.0 on the corresponding tested commit. Upload these two assets and use RELEASE-NOTES-1.0.0.md. Do not attach a debug APK. Update website and README download links only after the release exists.
